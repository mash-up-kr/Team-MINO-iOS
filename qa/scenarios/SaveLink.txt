# SaveLink 골든 패스: 공유받은 링크를 방에 저장하고 시트가 닫히는 주 동선.
#
# 전제: 이 화면은 **Share Extension** 안에서 뜬다. 앱을 launch 해서는 도달할 수 없고,
#   호스트 앱(Safari 등)의 공유시트에서 "꾹"을 눌러야 한다. 공유시트는 별도 프로세스라
#   AXe 의 describe-ui 에 잡히지 않아 그 두 스텝(공유 버튼 → 꾹)은 좌표 탭으로만 가능하다.
#   → **이 시나리오는 수동 확인 대상이다.** simulator-qa 가 자동으로 돌리지 못한다.
#
# 저장 버튼(MHActionArea)에는 식별자를 두지 않았다 — 방 미선택 시 비활성이라
#   탭 스텝의 성공/실패가 선택 상태에 의존한다. 활성화 여부는 스크린샷으로 판정한다.
#
# 방 목록은 표본 데이터(SharedRoom.samples, 5개)라 본앱을 실행하지 않아도 보인다.
#   SaveLink.room.2("성수 카페 투어")는 이미 저장된 방으로 고정 주입돼 있어
#   (ShareViewController 의 savedRoomIDs: ["2"]) 체크된 채 비활성이다.
#
# 수동 절차:
#   1. Safari 에서 아무 페이지를 열고 공유 → "꾹" 을 누른다.
#   2. SaveLink.header 에 "게시물 저장" 이 보이고, 표본 방이 5개라 시트 높이가 644 인지 확인한다.
#   3. SaveLink.room.2 가 회색 체크(비활성)이고, 눌러도 체크가 풀리지 않으며
#      저장 버튼도 활성화되지 않는지 확인한다.
#   4. SaveLink.room.1 과 SaveLink.room.3 을 눌러 체크된다.
#   5. 저장 버튼이 활성화되면 누른다.
#   6. 시트가 곧바로 걷히고 SaveLink.completionSnackbar 만 남는다(뒤는 호스트 화면).
#      약 1.2초 뒤 익스텐션이 스스로 닫힌다.
#   7. 호스트 앱(Safari)으로 돌아온다.
#
# 되돌아가기: 시트 밖(위쪽 빈 영역) 탭으로 저장 없이 닫힌다. 닫기 버튼과 딤은 없다 —
#   시트 뒤로 호스트 화면이 그대로 비친다.
#   저장 중에는 이 탭이 먹지 않지만(reducer 의 isSaving 가드), 지금은 저장이 stub 이라
#   그 구간이 눈에 안 잡힌다 — 검증은 SaveLinkReducerTests 가 맡는다.
#
# 실행 스텝이 없는 이유: 익스텐션은 호스트 앱과 별개 프로세스라 AXe 의 describe-ui 에
#   우리 화면이 잡히지 않는다(익스텐션이 떠 있어도 호스트 앱만 보인다). 매니페스트의
#   식별자는 XCUITest 를 붙일 때를 위해 남겨두고, 지금 검증은 위 수동 절차로만 한다.
